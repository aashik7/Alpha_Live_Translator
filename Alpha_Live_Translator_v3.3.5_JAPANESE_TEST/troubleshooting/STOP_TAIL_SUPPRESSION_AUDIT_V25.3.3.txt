5. PROTECTION OF EXISTING VALID ACTIVE RECORDS
================================================================================
Guards present:
  - Ledger mutations blocked after freeze_snapshot()
  - suppress requires suppression_reason
  - completed_previous_sentence_protected can block unsafe revise (separate path)
  - NO explicit guard in suppress path that target must equal the incomplete tail candidate
  - NO check that target record is itself incomplete or stop_flush before suppress

When suppress_early fires:
  - revision_target_id typically points at previous_record.line_id / _last_stable_line_id
  - That is an EXISTING active ledger record (often the last committed stable line)
  - _suppress_record_unlocked deactivates that record without verifying it is the tail fragment

================================================================================
6. CONCLUSION — CAN INCOMPLETE STOP TAIL SUPPRESS AN EXISTING ACTIVE RECORD?
================================================================================
YES (under current code, when flags enabled and suppress_early conditions met).

An incomplete Stop tail with no strong sentence end can invoke ledger suppress against
revision_target_id derived from the previous stable line (existing active record). The
ledger will mark that record suppressed/active=False even if it was a prior valid commit,
not merely a discardable partial tail record.

This audit does not assert the behavior is correct or incorrect — only documents current code.
